* DONE Work on FLTKAda reports examples/Fonts.Mod can't record the top left dot
Found 2026-11-05 by FLTKAda, porting FLTK's test/fonts.cxx; recorded
there as FLTK-issues.md F30.

In the vector font editor (F1), a click on the top left dot adds
nothing, so a stroke begun there starts at the second dot. Each
letter's strokes are a row of vec ended by 0X, and a dot is stored as
column * 8 + row, so the top left dot is 0X too. AddCmd finds the first
0X, writes the dot's 0X there, and the row is unchanged. fonts.cxx has
the same bug (add_point_cb, vec[255][128]), which Fonts.Mod copied.

The saved table (SaveCB) is a C string per letter, so a 0 inside one
would end it. FLTKAda's port leaves the dot out on purpose, with a
comment; a fix that records it would need another encoding, such as
storing column * 8 + row + 1, for both the editor and the saved table.
Not checked in pofltk itself: this is from reading Fonts.Mod, which
shares fonts.cxx's encoding.

Done 2026-11-06: confirmed, and fixed by storing each command plus 1;
the saved table leaves the dot out, with an alert (doc/fltk-issues.md,
146).
